# Rhythm Speaker レッスン検索 独立試験環境

## 構成

Cloudflare Workers が Google Calendar API を読み取り専用で取得し、静的画面と同じ URL の `/api/classes` で公開用の項目だけ返す。Vercel Functions 用の代替アダプターも同梱。どちらも GitHub Pages の JSON や既存同期処理を参照しない。

Google 認証のスコープは `calendar.events.readonly`。東京時間の当日から90日間を対象に繰り返しを展開する。APIはリクエストごとにGoogleから取得し、予定をキャッシュしない。公開承認が厳密に `true` でない場合、または取得に失敗した場合は HTTP 503、予定0件、申込不可を返す。取得に成功した結果が空の場合は HTTP 200。

| 原本の状態 | 公開結果 |
| --- | --- |
| 非公開・機密 | 行ごと除外 |
| 削除・Google側の `status=cancelled` | 行ごと除外。Google側で削除と取消が同じ状態になる場合があるため、旧名称や担当を復元しない |
| 現在も公開対象で、分類できるタイトルの末尾が `CANCELLED` | 開催中止として表示、申込不可 |
| 分類できるタイトルの末尾が `CLOSE` | 受付停止 |
| 担当情報なし、要問い合わせ指定、確定前 | 要問い合わせ。公式LINEの一般相談だけを案内 |
| 分類できないタイトル | 表示対象外 |

クラス判定は STEP、TAP、STRETCH、ISOLATION、BAR、HIIT のクラス名に加え、区切りと所要時間を含む形式が必要。既存Pythonは末尾 `CLOSE` 以外の確定予定を原則 `OPEN` とする。試験版も分類済みで講師が明記された確定予定は、`OPEN` が省略されていても申込可能。新しいクラス名の追加時は分類対象を見直す。残席情報は返さない。

申込文面を作る時とLINE・メールを開く直前に、予定を読み直す。外部アプリで文面を送信する時点までの状態は保証できない。既にブラウザに表示された情報は次の取得まで残り得る。複数拠点で旧版を混在運用しない。キャッシュ廃止に伴う応答時間とGoogle APIの割当は実接続後に計測する。

開発・検証の参照先は `feat/schedule-calendar-v2-direct` のこのディレクトリ。 `feat/schedule-calendar-v2-preview` は旧公開JSON方式の比較用。

## 独立環境のセットアップ

1. 既存 Watchdog と異なる Worker 名とアカウント範囲を確認する。
2. Google Cloud で Calendar API を使える試験用サービスアカウントを用意する。「レッスン296」に対する閲覧権限の付与は所有者承認後に行う。カレンダー全体を一般公開する必要はない。
3. Worker のシークレットに `RS_GOOGLE_SERVICE_ACCOUNT_JSON`、`RS_LESSON_CALENDAR_ID`、推測困難な `RS_SESSION_ID_KEY` を登録する。値はチャット・コミット・ログに記録しない。
4. 公開対象の原本と表示フィールドを承認した環境にのみ `RS_PUBLICATION_APPROVED=true` を設定する。資格情報未設定時は HTTP 503。Cloudflare の試験 Worker にだけ `wrangler deploy` を実行する。
5. Vercel を使う場合は商用利用可能な契約を事前確認し、独立プロジェクトだけを対象にする。Vercel アダプターも予定をキャッシュしない。

## 検証・移行

- `node --test worker/calendar.test.mjs` で投影、繰り返し例外・変更、削除、障害・遅延を確認。
- 実接続後、原本と11月5日の7件の日付・時刻・担当・状態を照合する。別のテストカレンダーで新規・変更・削除の反映時間を測定し、許容時間を超える場合は移行を保留。
- 320、375、390、430、768、1440px で初期表示、月移動、選択、絞り込み、日本語入力、詳細、LINE・メール、再読み込み、キーボード操作、表示エラーを確認する。連絡は送信しない。
- 本番切替は別途承認後に公式ページの参照先を変更する差分として実施する。問題時はその差分を戻し、従来のページと取得経路に戻す。
