# リズムスピーカー商店｜アフィリエイトリンク登録・公開引継ぎ運用 v3.0

更新基準日: 2026-11-18 JST
Status: OPERATIONAL。最新 `shoten/ops/PRODUCT_OPERATIONS_V1.md` v3.0 の本人提供リンク直接受理・写真任意・一括公開・DONE判定を優先する。本書の過去の件数・写真・追加リンク確認の記述を公開停止理由にしない。

## 目的 / DONE
このチャットを商品マスター・Amazonアソシエイトリンクの専門受付とし、既存の7カテゴリ×5商品＝35商品を段階的に検品・登録・本番掲載する。最終DONEは「35の正式商品が `/shoten/` で表示され、写真または代替表示と購入CTAが正しく機能すること」。リンク取得だけ、PR作成だけはDONEではない。

## 権限・正本
- 商品・リンク・承認・配置の上流正本: private `noritap/AMAZON_COMMERCE_DATA_OS` の `data/products.json`, `data/affiliate_links.json`, `data/approvals.json`, `data/placements.json` ほか。READMEや古い現状表より実データ優先。
- 公開表示データ: `noritap/rhythmspeaker` main `shoten/catalog.json`。商品・記事UIは `shoten/editorial.js`、`shoten/data-adapter.js` 等。
- 共通の開発ルール: `noritap/AI_OS_CREATION_RULES`。公式HPの `PROJECT_PROFILE.md` に従い /shoten/ 外への変更は原則しない。
- このファイルは運用指示であり、商品承認・Amazon媒体登録・商品画像の利用許諾を自動的に与えない。

## 現在値の扱い
古いスナップショット（2026-11-13時点の4件・5リンク・35件目標など）は現在値ではない。商品・リンク・承認・配置・公開件数は作業時の最新mainと実際の本番を読み取って報告する。公開目標は固定35件に拘束しない。未承認商品を掲載しない。

## 1商品ずつの会話入力
通常は `商品名または既存商品ID + 本人がAmazonで発行した正式アソシエイトURL` の2点だけ受け取る。既存台帳から商品同一性・色・型番の不足を確認する。ただし本人提供の正式短縮リンクについてTracking ID・発行方法・転送先・検証日時を追加要求しない。画像は任意。複数URLの一括入力も可。
- 例: `RS-P0002 / https://link.amazon/...`
- 本人が発行していないリンクをAIが推測・組み立てない。通常のAmazon商品URLをアフィリエイトURLの代用にしない。

## 1件の処理順
1. 上流・公開の既存product_id、ASIN、型番、色、リンク、配置、承認情報を読取。既存IDは再利用し、重複禁止。
2. 入力リンクの形式、本人確認記録、対象商品の同一性、媒体適格性を検証。本人が対象商品を指定して提供した正式短縮URLは転送先本人確認済みとして受領し、同じ確認を再質問しない。AIが独立検証したとは偽らない。未解決の商品同一性だけを管理し、本人提供リンクの追加検証は要求しない。`OWNER_PROVIDED` と独立検証済み `VERIFIED` は区別する。
3. 写真は公開の必須条件ではない。使用する場合だけ実物との一致と公開利用条件を点検。本人の実使用・メーカー仕様・調査による説明を区別する。
4. 上流の products / affiliate_links / approvals / placements / assets を必要最小限更新。本人の承認記録を捏造せず、既存承認を再利用。
5. 既存 `tools/build_shoten_catalog.py` の承認済みデータ投影手順を優先。直接 `shoten/catalog.json` を更新する場合は上流正本との同期方式を明記。
6. `tools/validate_shoten_product_ops.py`, `tools/test_shoten_catalog.py` と関連CI、画像パス・JS構文など変更箇所に直結する検証。
7. PR作成・検証結果報告。公開承認の範囲を満たす場合のみmain統合とPages反映確認。公開後に商品詳細・画像・Amazon遷移先・広告表示を本番で確認。

## 状態定義
- `CANDIDATE`: 商品候補（正式商品名・同一性未確定を含む）
- `IDENTITY_VERIFIED`: メーカー・型番・ASIN照合済み
- `LINK_REVIEW`: アフィリエイトURLあり、本人発行・対象ASIN・媒体・タグなどの確認待ち
- `ASSET_REVIEW`: 使用予定画像の権利・公開文言の不足（画像がないだけなら公開を止めない）
- `READY_FOR_PUBLICATION`: すべての公開ゲートが揃い、統合待ち
- `PUBLISHED`: mainと本番で掲載・CTA・画像・広告表示確認済み
- `HOLD`: 方針不一致・権利・安全・商品同一性に問題あり

## 各応答の最低報告
`商品ID | 商品名 | 旧状態→新状態 | リンク確認 | 画像確認 | 上流更新 | 公開用更新 | PR/commit | CI | 本番確認 | 未完了/次の1アクション`。
リンクの存在、テスト合格、PR、マージ、デプロイ、実ブラウザ確認を区別する。数値は上流・公開両方の実ファイルから算出する。

## バッチ運用・優先順位
- 新規のOWNER_PROVIDEDリンクと未公開商品を差分抽出し、商品同一性・正式名・型番・説明出典・承認・掲載配置の不足を商品ごとに判定する。
- 本人公開承認が明示されている対象のみ、商品・リンク・承認・配置を同一バッチで整合させる。承認を捏造せず、他の商品を保留に巻き込まない。
- ④公開作業は最大20件を目安に、既存生成器へ明示的な --limit を指定し、公開カタログの全件保持・CI・main・本番表示を確認する。
- 新規公開数が0件なら、残る本人の判断が必要な商品名とIDをまとめて提示し、確認済みリンクを再調査しない。
- 見込み件数ではなく、本番で増えた商品数をDONE基準にする。
## よく使うチャット指示
- `登録: 商品名 / AmazonアソシエイトURL`: 1件照合・登録・公開準備
- `登録して公開: 商品名 / URL`: 検証と承認条件を満たす範囲で公開まで
- `一覧`: 上流と本番を照合し現在の確定・保留・不足一覧を表示
- `次`: 最も公開に近い商品と必要な本人作業を1件だけ提示
- `差分監査`: 最新mainの本人提供リンク・公開承認・掲載配置・本番の差分を検証

## 必須：1商品＝main統合・本番公開まで（v2.0 / 2026-11-13）
最上位のDONEは、リンクを保存したこと、PRを作成したこと、CIが通ったことではなく、**対象商品が商店の本番サイトで公開され、商品情報・画像・購入CTAを確認できたこと**。途中段階は明確に未完了として扱い、「次」を提示しない。

### 1商品ごとの手順
1. 受領：ユーザーが商品名または商品IDとAmazonアソシエイトURLを送る。
2. 同一性検査：既存ID、メーカー、型番、色、ASIN、短縮URLの転送先とTracking ID、元の承認記録を照合。別商品のID衝突を解消する。未検証の事実は書き込まない。
3. データ準備：上流Commerceのproducts/affiliate_links/approvals/placements、出典と画像の権利情報を最小差分で更新。正本と公開用catalogの内容を一致させる。
4. 公開用生成：公開用 `shoten/catalog.json` と画像など必要なファイルだけを更新。商品説明の実使用表現は根拠がある場合のみ。
5. 自動検証：JSON schema、上流エクスポート、商品検証、リンク形式、商品画像、CIを確認。失敗時は原因に直結する最小修正だけ行う。チェックの期待値を実態に合わせて修正する場合でも、本人承認・商品同一性・リンク・画像権利の安全条件は緩和しない。
6. GitHubの両リポジトリでPRを確認し、必要な承認と検証が揃えばmain統合。上流と公開側の相互参照・コミットを記録する。
7. GitHub Pagesの本番反映を確認。対象商品詳細、画像、Amazon購入CTA、広告表示、スマホ表示を実ブラウザで確認し、完了と報告する。

### 次へ進む条件
- **PUBLISHED（DONE）**：商品情報・リンク・画像の一致、正式承認、CI、main統合、本番反映、購入導線確認を完了した場合のみ「次」を提示。
- **BLOCKED（STOP）**：ASIN/短縮URL転送先/Tracking ID/画像利用条件など公開に不可欠な証拠がなく、権限内で解決できない場合。リンクはPENDINGとして安全に保存できるが、未公開を完了扱いしない。次の商品へ進まず、本人に必要な最小限の1項目を明示。
- **FAILED（STOP）**：CI失敗、マージ不能、本番未反映、リンク誤誘導等。再試行で無限に利用枠を消費せず、最小の修復または復旧に限定。
- ユーザーが明示して「保留・スキップ」と指示した場合のみ、未完了の商品を保留台帳へ残したうえで次候補に移動できる。
- 「おすすめしない」は掲載候補から除外。既存の承認済み商品や購入リンクを無断削除しない。

### 簡潔な報告形式
`RS-Pxxxx 商品名｜GitHub main: 完了/未完了｜本番: 公開完了/未完了｜次: 商品名（公開完了時のみ）`
失敗・停止時は理由と必要な確認を1行加える。PR作成、ブランチ保存、上流リンク登録だけの場合は本番公開と区別する。
