## 運用ルールとの整合
1. **本人提供リンクの再確認はしない。** 各URLは上流リンク台帳に原文のまま保持済み。`OWNER_PROVIDED` は独立検証の `VERIFIED` とは区別する。URLの形式は既存の安全な検査を利用する。
2. **ASINを推測しない。** メーカー型番やJANが判明していてもAmazon内部の商品識別コードと取り違えない。既存 `tools/build_shoten_catalog.py` は承認済み商品のASIN整合を要求する。本人リンクの転送先再検証ではなく、商品識別として必要な証拠を最小限で用意する。
3. **公開承認を捏造しない。** 本人が対象IDを明示して公開承認した範囲だけ `products` / `approvals` / `placements` を整合更新する。承認がない場合は準備状態のままにする。
4. **写真は必須にしない。** 画像なしの場合は既存の代替表示を使用する。画像追加は別途並行して進められる。
5. **個別の問題でバッチ全体を停止しない。** 識別・承認の完了した商品だけを選択し、`--limit` を明示して既存生成器で全公開商品を保持したまま反映する。
6. **DONEは本番確認。** 上流更新 → カタログ生成 → テスト → CI → main統合 → GitHub Pages表示・購入CTA・広告表示を確認する。PR作成のみを公開とは報告しない。
