# リズムスピーカー商店｜商品選定・掲載運用 v1.1

## 目的と正本
目的は「適切な商品を少ない作業で安全に公開し、タプ太郎ブログから購入につなげる」こと。新CMS・DBは導入しない。
- 本番の商品表示データ: `shoten/catalog.json`。ID `RS-P0001` 形式で採番し再利用しない。
- 商品・リンクの承認履歴が別の正本に存在する場合は、その承認フローを優先する。表示用catalogへの手入力だけで未承認商品を公開しない。
- 商品画像: `shoten/assets/products/`。記事URLは商品レコードの `blogArticle`（公開後のみ）。
- 既存 `shoten/data-adapter.js`、`shoten/catalog-core.js` のリンク検証を維持する。

## 1. 候補の選定（100点）
読者への役立ち度30、情報の信頼性25、購入可能性20、独自性15、制作保守効率10。
80点以上: 優先検品。65〜79点: 情報追加後に再評価。64点以下: 保留。
採点は掲載承認ではない。各項目の根拠、実使用か調査のみかを記録する。使用していない商品を「使った」と書かない。
候補の記録は `shoten/ops/product-candidate.template.json` をコピーして作成する。テンプレート自体は公開商品データに読み込まれない。

## 2. 公開前の必須検品
1. メーカー正式名・型番・ASIN・商品写真が同一モデルであることを照合する。色違い・旧型番に注意。
2. 仕様はメーカー一次資料で確認。数値・使用モード・条件を明記し、未検証の体験談は書かない。
3. AmazonアソシエイトURLは本人が取得・転送先・対象ASIN・紹介タグを確認。短縮URLは `AMAZON_OFFICIAL_SHORT` と `ownerVerifiedShortLink: true` が必要。未確認リンク・通常商品URLを購入導線に流用しない。既存RS-P0001のURLは変更しない。
4. 画像は権利・掲載許諾を確認し、原則3〜5枚をWebP化。実写とメーカー提供素材を区別し、`alt` を実物に一致させる。画像が1枚でも正確な情報を優先。
5. PR表示と注意点を掲載。変動する価格・在庫・レビュー件数は固定表示しない。

## 3. 商品登録・公開
1. 承認済みデータを基に `shoten/catalog.json` の `products` に1件追加。既存フィールドを流用。カテゴリは `shoten/editorial.js` の既存値を優先。
2. 画像を `shoten/assets/products/` に登録し、参照パスを検証。
3. `python3 tools/validate_shoten_product_ops.py` を実行。既存の `python3 tools/test_shoten_catalog.py` とCIも実行。
4. PR → CI全件合格 → main統合 → GitHub Pages反映 → スマホ・画像・購入URL・広告表示を本番で確認。
5. 本番実購入やAmazonの紹介料発生は検証の必須条件にしない。転送先確認は本人の承認・確認を優先。

## 4. タプ太郎ブログ連携
商店の正式商品ページを先に公開。はてなブログ `https://rhythmspeaker.hatenablog.com/` に商品記事を公開し、商品詳細URLを掲載する。
ブログ公開後に `blogArticle: { "url": "https://rhythmspeaker.hatenablog.com/entry/...", "title": "記事タイトル" }` をcatalogに追加して相互リンク。
記事内の商品カードは必ず正式型番・ASINを再確認。旧モデルへの誤誘導を禁止。記事を更新できない場合は不一致カードを撤去する。

## 5. 公開後の測定
週次で商品ページ閲覧、ブログから商店への流入、Amazonボタンクリック（取得可能な既存分析のみ）、Amazonアソシエイトの実績を記録する。分析機能が未導入の場合は「取得不可」と記載し、推測値を使わない。
商品ごとに「商品ID／公開日／記事URL／確認日／閲覧数／Amazon遷移数／紹介料／更新判断」を残す。分析のためだけの新DBやトラッキングシステムは作らない。
初期運用は週1〜2商品を上限目安にし、制作時間と成果で調整。

## 公開ゲート
型番・ASIN一致、アソシエイトURL本人確認、画像権利、広告表記、CI、main、本番確認のいずれか未完了なら未公開として報告。調査・PR作成・本番公開を混同しない。

## 表示ポリシー（共通・最優先）
- **ASINは内部照合専用。商店の利用者向け画面・商品詳細・比較表・カード・記事・メニューに表示しない。** トラッキングIDやリンク管理用IDも利用者に表示しない。
- 内部の `data/products.json` と公開配信用 `shoten/catalog.json` にはASINを保持してよい。これはURL同一性検査・重複防止・安全なアフィリエイト導線に必要であり、表示を意味しない。
- 比較表は「型番」のみ表示。ASINを使用した検索の内部照合は維持可能。ただし画面に検索結果としてASINを表示しない。
- サイトの表示内容、タプ太郎ブログの紹介文、ChatGPTの通常の商品提案・進捗報告にもASINを原則出さない。問題調査で識別番号が必須の場合だけ内部監査報告に限って用いる。
- どのチャット・Work/Codexから作業しても、このファイルの共通方針を優先。必要な変更は正式な正本を更新し、別の指示書との矛盾を解消してから公開する。
- UI検査の必須項目：商品詳細と2件以上の比較表を開いて、画面に `ASIN` のラベル・識別コードが表示されないこと。
