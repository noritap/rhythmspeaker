# リズムスピーカー商店｜商品選定・掲載運用 v3.0

## 目的と正本
目的は「適切な商品を少ない作業で安全に公開し、タプ太郎ブログから購入につなげる」こと。新CMS・DBは導入しない。
- 本番の商品表示データ: `shoten/catalog.json`。ID `RS-P0001` 形式で採番し再利用しない。
- 商品・リンクの承認履歴が別の正本に存在する場合は、その承認フローを優先する。表示用catalogへの手入力だけで未承認商品を公開しない。
- 商品画像: `shoten/assets/products/`。記事URLは商品レコードの `blogArticle`（公開後のみ）。
- 既存 `shoten/data-adapter.js`、`shoten/catalog-core.js` のリンク検証を維持する。

## 1. 候補の選定・検索（v2.3／Amazon.co.jp限定・100点）
目的は「Amazon.co.jpで実際に購入でき、読者にとって価値のある商品」を、検証可能な証拠に基づいて少ない作業で選ぶこと。商品の品質・Amazon内での購入条件・商店での紹介価値を分けて評価する。単なる最低価格では選ばない。

**商品開拓・価格比較・販売店選定・購入導線はAmazon.co.jp限定。** 楽天、Yahoo!ショッピング、アスクル、コストコ、メーカー直販等の他ECサイトから候補商品を検索・採用したり、他店価格を推薦順位・得点の根拠に使わない。Amazon.co.jpで商品ページと購入可能性を確認できないものは「Amazon掲載未確認」として候補の確定・推薦・正式登録を保留する。メーカー公式サイト等の一次情報は**仕様・安全性の裏取りに限り**参照でき、販売先の探索には使わない。

### 1-1. 採点前の必須適合ゲート
- 用途、規格、容量/数量、使用環境、互換性、安全性・法令上の注意点を確認する。重大な不適合や確認済みの安全上の問題があれば採点対象から除外する。
- 同等品比較では機能・剤形・規格を揃える（例：泡ハンドソープは液体用と混同しない、薬用と非薬用を区別、対応ディスペンサーを確認）。性能が異なるものは「代替候補」と明示する。
- 検証不能な必須条件があれば「要確認」として推薦を確定しない。確認できない価格・仕様に推測値を補わない。

### 1-2. 検索ルール
1. 用途と購入条件（容量、予算、必要機能、消費頻度、対象読者）を決める。
2. 商品名指定でも、Amazon.co.jp内で同一商品の複数出品・容量違い・セット品と、同等品・代替品を探索。原則5件以上を入口とし、ブランド・廉価品・業務用/まとめ買いなど比較対象の多様性を優先。候補が少ない場合は無理に埋めず理由を記録。Amazon.co.jp以外の商品掲載ページを検索対象にしない。
3. Amazon.co.jp上の正式名・型番・容量・数量・仕様・販売主体を照合。必要に応じメーカー一次資料で仕様と安全性を裏取りし、Amazon掲載情報との差異を記録。
4. 同一商品・同等品は**支払総額（税込商品代金＋送料－確認可能な即時値引き）**と**比較単位当たり実質価格**で比較。会員費、定期便、クーポン、地域送料、販売単位、使用期限、保管性・初期支出を分けて明記。未確定の割引・ポイント還元を現金値引きと同列に扱わない。
5. Amazon.co.jp内で同一・同等商品の出品価格、容量単価、定期便条件、配送・入手性、出品者とセット数量を比較。Amazon以外の他店価格は収集・採点しない。アソシエイト紹介料率を理由に読者の利益を損なう順位付けはしない。
6. 価格・在庫・出品者・レビュー等の変動データには確認日、情報源、未確認条件を付ける。最安値の断定は比較範囲と同一時点の確認がある場合に限る。価格が比較できなければ「暫定評価」。
7. 原則として同一条件で有力候補を比較でき、追加探索による改善可能性が小さくなった時点で検索を止める。際限ない検索や無意味な件数合わせは行わない。

### 1-3. 検索漏れ防止と商品ページ確認（v2.3追加・必須）
**A. 主要ブランド照合ゲート**
- 商品ジャンルの代表的ブランド・定番品をAmazon.co.jp内で個別検索する。単一の広域検索結果だけで「最有力」「最安」と判定しない。
- 業務用・大容量・低価格帯など、ユーザーの用途に応じた検索語を併用し、同一ブランドの容量違い・詰め替え用・セット品・旧新モデルを調べる。
- 少なくとも主要候補・廉価候補・容量違いの存在確認を行う。調査したブランド、検索語、発見した候補、見つからなかったものを候補記録に残す。
- すでにユーザーが提示した有力商品は、重複排除・比較の基準候補として必ず照合する。商品識別情報は内部照合にのみ使用し、利用者向けには表示しない。

**B. Amazon商品ページ直接確認ゲート**
- 推奨上位候補はAmazon.co.jpの商品詳細ページを直接確認し、正式商品名・ブランド・容量・数量・剤形・バリエーション・価格・在庫/購入可否・販売者/発送者・商品識別情報・確認日時を照合する。
- 検索一覧や商品検索ツールの断片だけでは、価格・販売条件を確定しない。商品ページがアクセス制限等で取得できなかった場合は「商品ページ未確認」と記録し、事実を推測で埋めず暫定候補とする。
- 本人が提供したAmazon商品ページ資料やスクリーンショットは、取得日時と条件を明示して一次確認資料として照合できる。ただし本人の条件付き画面を全購入者共通の価格と断定しない。
- ユーザー提供の正式アソシエイトリンクについては、既存の「本人提供Amazon短縮URLの受領・再確認省略」規則を優先する。商品ページの調査失敗を理由に、同一リンクの転送先確認を何度も要求しない。

**C. 購入方式・容量別価格比較ゲート**
- Amazon.co.jp内で、通常1回購入価格、定期おトク便価格、容量違い、セット/まとめ買いを**別枠**で確認する。定期便の割引率、初回/継続条件、クーポン、会員条件、送料、価格の取得日時を記録する。
- 比較単価は「条件を満たす実支払総額 ÷ 実容量（または数量）」で統一。送料等が未確認なら「商品価格ベース」と明記し、実質最安を確定しない。
- 定期便の金額を通常購入価格として表示しない。Amazonのアカウント・配送先・契約条件に依存する価格は、取得画面の条件付き価格として表示する。
- 対象用途に適合しない液体タイプや異なる薬用区分等は、安価でも同等商品として順位付けしない。Amazon内の同等候補のみ価格順位付けする。

**D. 検索完了判定・例外**
- 「主要ブランド照合済み」「上位候補の商品ページ確認状況を明記」「購入方式と容量単価の比較済み」「ユーザー提示候補の照合済み」を完了チェックとする。確認不能な項目がある場合、検索作業自体は完了可能だが推薦順位と得点は暫定と明示。
- 比較対象の範囲と日時を示さずに「Amazon最安」「最も売れている」などの無限定な断定をしない。推測に基づくレビュー数・購入数・価格は作成しない。
- 検索を繰り返すだけで新しい重要候補が増えない場合は、確認範囲と限界を記録して止める。追加調査・自動化基盤構築を公開の必須条件にしない。

### 1-4. 採点項目（100点）
- 実質コストパフォーマンス **25**：送料込み単価、同等品比、購入総額、継続費用。価格だけでなく同等機能を満たすことが前提。
- 品質・安全性・適合性 **20**：メーカー仕様、互換性、使用条件、品質根拠と留意点。
- 実際の購買需要 **20**：用途の明確さ、読者の課題、必要性、季節性。検索人気だけで需要を断定しない。
- 購入利便性・Amazon競争力 **15**：Amazon.co.jp内での販売条件、在庫/配送/出品者/同等品・容量違い比較。リンク未提供を商品の低品質と混同しない。
- 継続購入・収益可能性 **10**：消耗頻度・再購入適性・導線。収益は推測と実績を区別し、読者利益を優先。
- 情報の信頼性 **5**：一次情報・照合・確認日・実使用根拠。
- 制作・維持効率 **5**：既存資産・情報更新負荷・掲載作業量。
合計は100点。各項目は得点と根拠を記録し、実測・一次情報・推定・未確認を区別する。カテゴリ別の補助観点（消耗品は容量単価/補充頻度、家電は性能/耐久・消費電力、食品は成分/賞味期限等）を採用しても、基本配点は変えず根拠欄で補足する。

### 1-5. 判定と記録
- 80点以上：優先検品。65〜79点：情報追加後に再評価。64点以下：保留。
- Amazon.co.jp掲載・購入可能性、必須適合、価格確認、情報鮮度、公開承認は**採点とは独立したゲート**。高得点だけでは公開しない。比較価格が未確認なら暫定評価であることを明記。
- 使用していない商品を「使った」と書かない。候補記録は `shoten/ops/product-candidate.template.json` を用い、既存商品IDを再採番しない。
- 公開後は既存の週次指標を用いて推薦・優先度を見直す。分析取得不能時は「取得不可」とし、仮の転換率や紹介料を作らない。

## 2. 公開前の必須検品
1. メーカー正式名・型番・ASIN・商品写真が同一モデルであることを照合する。色違い・旧型番に注意。
2. 仕様はメーカー一次資料で確認。数値・使用モード・条件を明記し、未検証の体験談は書かない。
3. **本人が対象商品とともに直接提供した公式Amazonアソシエイト短縮URLは、そのまま受理し、Tracking ID・発行方法・転送先・追加の検証日時を一切求めない。** URLの文字列形式と提供記録は保持する。本人提供の出所は `OWNER_PROVIDED` として記録する。無関係なURLや通常商品URLを勝手にアフィリエイトリンク化しない。既存RS-P0001のURLは変更しない。
4. **画像は任意だが、商品写真を優先。** オーナーが当商店での掲載許可を確認済みと明言した対象商品写真は、同じ許諾確認を毎回本人に繰り返さない。確認方法は下記「7. 商品写真の本人許諾宣言」を適用し、商品同一性・技術検査を行う。画像が取得できなくても商品情報・正式リンク・公開承認・代替表示の条件が揃えば公開可能。
5. PR表示と注意点を掲載。変動する価格・在庫・レビュー件数は固定表示しない。

## 3. 商品登録・公開
1. 承認済みデータを基に `shoten/catalog.json` の `products` に1件追加。既存フィールドを流用。カテゴリは `shoten/editorial.js` の既存値を優先。
2. 写真がある場合のみ `shoten/assets/products/` へ登録し、参照パスを検証する。写真なしなら `approvedPhoto: null`・空の`gallery`で代替表示を検証する。
3. `python3 tools/validate_shoten_product_ops.py` を実行。既存の `python3 tools/test_shoten_catalog.py` とCIも実行。
4. PR → CI全件合格 → main統合 → GitHub Pages反映 → スマホ・画像・購入URL・広告表示を本番で確認。
5. 本番実購入やAmazonの紹介料発生は検証の必須条件にしない。転送先確認は本人の承認・確認を優先。

## 4. タプ太郎ブログ連携
商店の正式商品ページを先に公開。はてなブログ `https://rhythmspeaker.hatenablog.com/` に商品記事を公開し、商品詳細URLを掲載する。
ブログ公開後に `blogArticle: { "url": "https://rhythmspeaker.hatenablog.com/entry/...", "title": "記事タイトル" }` をcatalogに追加して相互リンク。
記事内の商品カードは必ず正式型番・ASINを再確認。旧モデルへの誤誘導を禁止。記事を更新できない場合は不一致カードを撤去する。

## 5. 公開後の測定
週次で商品ページ閲覧、ブログから商店への流入、Amazonボタンクリック（取得可能な既存分析のみ）、Amazonアソシエイトの実績を記録する。分析機能が未導入の場合は「取得不可」と記載し、推測値を使わない。
商品ごとに「商品ID／公開日／記事URL／確認日／閲覧数／Amazon遷移数／紹介料／更新判断」を残す。分析のためだけの新DBやトラッキングシステムは作らない。
初期運用の週1〜2商品制限を廃止。④本番公開チャットは1回最大20商品の一括公開を目標とし、本人承認・正確な商品識別・広告表示・本番検証を満たすものを優先する。

## 公開ゲート
型番・ASIN一致、正式アソシエイトURL確認、オーナー公開承認、広告表記、CI、main、本番確認が未完了なら未公開として報告。画像は任意。画像利用の許諾根拠は本人の対象範囲内の宣言を受領して記録し、同じ許諾質問を再実施しない。商品一致・画像ファイル形式・パス・altと広告表示は必須。写真なしの場合は代替表示の確認が必須。調査・PR作成・本番公開を混同しない。

## 表示ポリシー（共通・最優先）
- **ASINは内部照合専用。商店の利用者向け画面・商品詳細・比較表・カード・記事・メニューに表示しない。** トラッキングIDやリンク管理用IDも利用者に表示しない。
- 内部の `data/products.json` と公開配信用 `shoten/catalog.json` にはASINを保持してよい。これはURL同一性検査・重複防止・安全なアフィリエイト導線に必要であり、表示を意味しない。
- 比較表は「型番」のみ表示。ASINを使用した検索の内部照合は維持可能。ただし画面に検索結果としてASINを表示しない。
- サイトの表示内容、タプ太郎ブログの紹介文、ChatGPTの通常の商品提案・進捗報告にもASINを原則出さない。問題調査で識別番号が必須の場合だけ内部監査報告に限って用いる。
- どのチャット・Work/Codexから作業しても、このファイルの共通方針を優先。必要な変更は正式な正本を更新し、別の指示書との矛盾を解消してから公開する。
- UI検査の必須項目：商品詳細と2件以上の比較表を開いて、画面に `ASIN` のラベル・識別コードが表示されないこと。

## 本人提供Amazon短縮URLの直接受理（2026-11-18／最優先）
- ユーザーが商品を指定してAmazonアソシエイト短縮リンクを直接貼った時点で、リンクは本人提供のものとして正式受理する。
- **Tracking ID、発行方式、リンク転送先、検証日時を追加確認する工程と、それらの取得を公開条件にする規則を完全に削除する。**
- GitHubのリンク台帳は `OWNER_PROVIDED` として記録し、`VERIFIED`（独立検証）とは区別する。受け取ったURLは一字も書き換えない。
- 技術的な最低限の形式検査（`https://link.amazon/...`）は維持し、偽URLの誤登録を防ぐ。これは転送先確認とは異なる。
- 別条件の商品の正式名・型番、公開承認、掲載先登録、広告表示、本番動作は維持。写真の有無は公開条件にしない。

## 6. ④本番公開専用AI｜RELEASE FIRST 運用 v3.0（2026-11-18）
**完了条件は、対象商品が実際に公開HPで閲覧・購入リンク利用可能になり、本番の掲載数が増えること。** PR・CI・書類作成・候補抽出だけでは達成と見なさない。

1. 開始時に本番サイトの掲載件数とGitHub main SHAを固定し、まず未公開の本人提供リンク付き商品を抽出する。
2. **全件調査より、商品識別・正式名・本人提供リンク・出典が揃った商品から最短で掲載**。写真・価格比較・SEO・記事・詳細レビューは必須条件にしない。
3. 本人が当該商品を本番公開対象として指定、または公開を明示的に委任した範囲で、**その実際の指示をエビデンスとして1回だけ記録**。架空の個別承認は禁止。対象外の商品を勝手に承認しない。
4. 登録済みの `OWNER_PROVIDED` リンクは一切再検証しない。型番・数量・商品データ整合とURLの安全な形式のみ確認する。
5. 商品マスター・承認・掲載配置・カテゴリ・カタログを同一バッチで反映。承認がない商品は保留するが、他の掲載可能商品を止めない。
6. 既存カテゴリにない場合、既存UIと互換なカテゴリを最小追加する。カテゴリ未対応を理由に、本番公開を無期限延期しない。
7. 最大20件をまとめて処理。PR→CI→main→本番ブラウザで、件数増加・リンク・広告表示・画像代替表示を確認する。
8. 0件の場合、修復可能な不整合を修復したうえで、残る**本人の判断が必要な対象商品を具体的な商品名で一括提示**し、同じ監査を反復しない。
9. 公開後は次回から商品探索ではなく**前回残件と新規リンクの差分**だけ処理。週次の購入導線・売上改善に反映する。

## 7. 商品写真の本人許諾宣言・写真優先運用 v1.0（2026-11-18）

### 基本方針
オーナーは2026年11月18日の商店作業チャットで「写真は全て許可が降りている。ルール化して写真は使って良いルールにして」と明示した。本宣言は**商店掲載を意図して本人が提供・指定・使用承認した商品写真**に関する本人申告の利用許諾情報として取り扱う。毎回の再確認・画像ごとの同一質問を不要とする。**「本人が許諾済みと申告」**と記録し、AIが各権利者から独立して許諾を取得・検証したとの表現はしない。

- 対象: オーナーが商店で使うことを指定した写真、商店の商品マスターでオーナー許諾済みと記録された写真。すでに商店に登録されている画像は既存根拠を尊重する。
- 対象外: 未指定の外部サイトから新しく取得する写真、他人の人物・商標・ロゴを含む広告素材の第三者利用、第三者写真の無断加工・転載。Amazon掲載画像も、出所・取得方法ごとのAmazon側の利用条件が適用される可能性は残るため、本宣言を**あらゆる外部画像の無制限な再利用許可**とは解釈しない。
- 特定写真に利用制限・削除要請・権利上の相反情報が判明した場合、その写真だけ使用を停止・差し替える。他の登録可能商品の作業は止めない。

### 写真の優先順位と停止禁止
1. 指定・本人提供・掲載許可記録済みの**実商品の写真**を優先。商品ID、ブランド、型番、色、容量、数量、セット構成の一致を確認。
2. 取得できない場合は、商店所有の写真・作成済み素材・メーカーの利用条件が適合する画像を再利用。
3. それでも難しい場合は本人が承認した**オリジナルAI制作イメージ**を利用。画像内または商品付近に「AI制作イメージ（実物写真ではありません）」と明示。実在商品の外観・端子・ロゴ・性能を不正確に描いたものを実物写真として説明しない。
4. 画像の取得・変換が失敗しても、写真を公開の必須条件にせず商品掲載を続行。

### 最小登録ルール
- 商品写真: `imageSource` 等の既存フィールドに `owner_permission: OWNER_ATTESTED` または既存互換表記、出所URL／受領元、照合商品名、確認日を記録。外部に公開すべきでない証拠情報は公開カタログへ書かない。
- オリジナル画像: `image_type: AI_GENERATED_EDITORIAL_ILLUSTRATION`, `product_photo: false` を維持。
- ファイルは既存 `shoten/assets/products/` に保存し、可能ならWebPに最適化。既存対応のSVGも可。商品カードの `approvedPhoto`／`gallery`／`alt` と一致させる。
- 高品質基準: 一覧で視認できる明度・余白・背景の統一、スマホでの見切れなし、商品形状の誤認防止、見栄えと購入導線。架空の価格・体験談・効果を画像に書かない。
- 写真追加のみなら商品説明・アフィリンク・既存公開承認を変更しない。PR・CI・main・本番表示検証を別々に報告する。

### DONEの判定
写真の**許諾確認済み**と**画像ファイル取得済み**と**GitHub保存済み**と**カタログ紐付け済み**と**本番表示確認済み**を混同しない。本番で商品数・画像の描画・クリック導線が使えることを最終成果とする。

## 8. 常時委任による自動公開（2026-11-20）
オーナーは2026年11月20日に「情報が全て揃っていれば、私の確認なしでも公開するルール設計にしてほしい」「俺が介入しなくても自動で公開されていく設計でよい」と明示した。本節はこの常時委任に基づく公開手続きを定める。

- 下記の客観条件を**全て**満たす商品は、商品ごとの都度のオーナー確認なしに公開してよい。この場合、本節の常時委任が公開ゲートの「オーナー公開承認」に相当する。
  1. リンク台帳に当該商品のリンクがあり、status が `VERIFIED` または `OWNER_PROVIDED`（`OWNER_PROVIDED` は転送先検証なしで可。「本人提供Amazon短縮URLの直接受理」の節に従う）。
  2. 商品台帳の `asin` が登録済みで、形式が `[A-Z0-9]{10}` に一致する。
  3. `category_ids` のいずれかが生成器 `tools/build_shoten_catalog.py` の対応カテゴリに含まれる。
  4. `editorial`（紹介文）が存在する。
  5. ID衝突・台帳間の不整合などの異常がない。
- 公開時は、承認レコードの evidence に常時委任（2026-11-20 オーナー指示）である旨を明記し、配置レコードを作成してから生成・公開する。架空の個別承認は作らない。
- 条件が1つでも不足する商品は公開せず、不足理由を日次運営の報告に理由別に載せる。不足の解消自体は権限の範囲で進めてよいが、条件を推測で満たしたことにしない。
- ASINの推測、正式アソシエイトリンクの推測・捏造の禁止は、従来どおり維持する。本節は表示ポリシーと公開ゲートの他の要件（広告表記、CI、main統合、本番確認）を免除しない。
- オーナーはいつでもこの常時委任を撤回・変更できる。撤回・変更があった場合は本節を更新し、それ以降は変更後の条件に従う。
