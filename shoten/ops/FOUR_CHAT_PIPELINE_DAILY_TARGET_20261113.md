# リズムスピーカー商店｜4専用チャット・日次量産ルール v1.0
2026-11-13 / 作業ブランチ上の運用案

## GOAL
4チャットを明確に分け、1チャットの「進めて」1回で担当フェーズの一括処理を最後まで行う。毎商品ごとに質問・報告・作業中断しない。下流工程は上流商品の完了ゲートを必須とし、商品ID・通常URL・状態をGitHubで共通管理する。重複なく進め、処理数と完了数を区別する。

## 1. 商品開拓・文字データ20商品登録チャット
- 起動「進めて」→最新GitHub/上流正本を照合→既存20件バッチの未完了を優先→カテゴリバランス配慮で20件を一括調査・同一性/型番/メーカー仕様・国内Amazon通常URL照合→コピー制作→写真なし(null/[])→商品ID衝突検査→上流正本のレビュー/必要な正式登録→READYへの昇格→GitHub再取得・テスト→20件をまとめて最終報告。
- 「原稿作成だけ」「ID候補だけ」「PR作成だけ」で1商品ごとに止めない。権限と安全ゲートを満たすときは上流商品IDの正式登録まで同一実行に含める。
- 20件は目標。確定情報不足・権限・ツール限界で未達なら保存済/CONTENT_READY/READY/未完了を分け、未完了を次バッチへ引継ぐ。数合わせの虚偽登録を禁止。
- 完了判定: READY_FOR_AFFILIATE_LINK（写真任意、メーカー検品、原稿、カテゴリ、正式ID、Amazon通常URL、GitHub保存検証完了）。既存アフィリンク受領済は再取得不要。
- 他チャットの写真・アフィリンク・本番公開を待たない。

## 2. 写真登録チャット
- 起動「進めて」→登録済み画像不足商品を優先→利用権のある本人写真/メーカー許諾素材/Amazon認可API画像を照合→商品型番・色一致→アップロードと表示検証→画像状態台帳更新。
- 画像権利・利用可能なファイル/APIがない商品はHOLDして次へ。写真がないだけで1のREADYを取り消さない。無断転載・AIの偽製品写真禁止。
- 1回の数量は対応可能な最大数。素材不足で60件成功を偽らない。

## 3. 正式アフィリエイトリンク登録チャット
- 起動「進めて」→本人提供の正式リンクを一括照合→上流商品IDと正確に紐付け→承認状態を確認→上流台帳へ保存・検証。推測でリンク生成禁止。
- 受領済リンクを再要求しない。本人が未取得のリンクは自動生成不可、入力待ちとして他の商品を先に進める。
- 40件は当日の受領済/取得済正式URL数が前提。リンク受付だけで公開を代行しない。

## 4. 本番統合・公開チャット
- 起動「進めて」→公開承認・安全・正式リンク・画像の許諾と表示規約・PR/CI/レスポンシブ→公式HP main統合→GitHub Pages確認→実商品/CTA/広告/スマホQA→公開数を記録。
- 20件の公開は前工程の20件が公開ゲートを全通過した場合のみ。PRだけでPUBLISHEDにしない。
- 選択肢: 画像未整備でもテキスト中心表示が公開ゲートに適合するなら公開検討可。別の公開担当が最終判断。

## 共通の計測・引継ぎ
product_idを主キーにし、正式ID未定は候補キー。GitHub上で登録済・原稿完成・READY・画像登録・リンク登録・本番公開を別ステータスとして重複計上しない。1商品が同時に複数のフェーズに存在しても件数は重複して水増ししない。変更時は最新版再読取と衝突防止、テスト、コミット/PR/公開状況を区別。サイトmain/本番への変更はチャット4だけ。External upstream source dataはチャット1と3で必要な権限内の安全な登録を認める。
